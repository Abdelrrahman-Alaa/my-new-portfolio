# سجل الدروس المستفادة وتفادي الأخطاء (Lessons Learned & Anti-Patterns)

هذا الملف يمثل الذاكرة التراكمية للمشروع. أي خطأ يتم اكتشافه أو تصحيحه بواسطة المطور يتم تسجيله هنا فوراً كقاعدة ملزمة ومحفوظة حتى لا تتكرر نهائياً.

---

## 1. أخطاء التنسيق و Tailwind CSS v4 (تم التعلم بتاريخ 2026-09-16)

### ❌ الخطأ / الـ Anti-Pattern:
- استخدام قيم عشوائية بأقواس مربعة مثل `min-h-[44px]` أو `min-w-[44px]`.
- استخدام كلاسات التدرجات اللونية القديمة مثل `bg-gradient-to-t`.
- استخدام `stroke-[3]`.
- **نقل الكود القديم دون تدقيق أثناء الـ Refactor:** نسخ نفس الـ HTML/CSS القديم للمكونات الجديدة دون تحديثه لمعايير النسخة الأحدث.

### ✅ الحل المعياري الصارم:
- استخدام السلم القياسي لـ Tailwind: كل وحدة = 4px، وبالتالي 44px تُكتب دائماً **`min-h-11`** و **`min-w-11`**.
- في Tailwind v4، التدرج الخطي يُكتب دائماً: **`bg-linear-to-*`**.
- سُمك الخط يُكتب مباشرة: **`stroke-3`**.
- نسبة العرض للارتفاع 16:9 تُكتب دائماً بالصيغة القياسية **`aspect-video`** بدلاً من `aspect-16/9`.
- **قاعدة ذهبية في أي Refactoring:** أي كود يتم تفكيكه أو نقله يجب تدقيقه وتحديثه لمعايير النسخة الحالية (Code Audit & Modernization)، وليس مجرد نقله كما هو.

---

## 2. معايير إدارة الحالة والـ Server Components

### ❌ الخطأ / الـ Anti-Pattern:
- وضع `"use client"` في أعلى الصفحة أو في كومبوننت رئيسي دون حاجة لتفاعلية، مما يعطل ميزات الـ Server Components والـ SEO والسرعة.

### ✅ الحل المعياري الصارم:
- دفع `"use client"` دائماً إلى أطراف الشجرة (Leaf Nodes)، والاحتفاظ بالأغلفة والصفحات الرئيسية كـ Server Components نقية كلما أمكن ذلك.

---

## 3. افتراض بيانات شخصية أو معمارية دون الرجوع للمطور (تم التعلم بتاريخ 2026-09-16)

### ❌ الخطأ / الـ Anti-Pattern:
- **افتراض بيانات العمل أو الهوية (Business/Personal Data Assumptions):** كتابة دومين افتراضي من دماغ الـ AI (مثل `https://abdelrahman-alaa.dev`) في ملفات مثل `robots.ts` و `sitemap.ts` و `layout.tsx`.
- صياغة نصوص الـ SEO، والعناوين، والوصف، وبيانات الـ JSON-LD دون استشارة المطور في الصياغة التي تمثله وتمثل علامته الشخصية ونطاقه الحقيقي.
- التعامل مع موافقة المستخدم على فكرة (مثل "ضيف SEO") كإذن مفتوح لملء البيانات ببيانات وهمية/مفترضة بدلاً من طرح أسئلة استكشافية للحصول على البيانات الحقيقية.

### ✅ الحل المعياري الصارم:
- **صفر افتراضات في البيانات (Zero-Assumption Data Policy):** لا يتم كتابة أي دومين، أو وسوم SEO شخصية، أو روابط تواصل، أو نصوص هوية دون سؤال المطور عنها مسبقاً وتخييره في كيفية إدارتها.
- الاعتماد على متغيرات البيئة (`process.env.NEXT_PUBLIC_SITE_URL`) وطلب القيمة الحقيقية منه، أو استخدام Placeholder واضح وصريح لحين تزويدنا بالبيانات الحقيقية.
